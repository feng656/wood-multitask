> 本目录（多任务模型·未消融）中「未消融」指：bridge 有无、BiCRR 有无两个变量的消融训练尚未完成。本文件汇总已定方案、代码入口与执行顺序，供后续会话直接接续。

## 1. 消融阶梯（已定方案）

按单一变量原则逐级训练，每级与三条独立基线在**固定 test 同口径**比较：

```
三条独立基线（已完成）
  ↓
Shared MT NO Bridge   ← v1/v2 已完成（本目录 05_）
  ↓ ⏳ 未训练
Shared MT + Bridge（bridge 任务与数据恢复，其余配置与 v2 完全一致）
  ↓ ⏳ 未训练
Shared MT + Bridge + BiCRR（年轮-缺陷关系建模模块）
  ↓ ⏳ 未训练
BiCRR + Bridge 最终模型
```

- 每级沿用 v2 定版配置（512 steps / letterbox 640 / thin_crack / 分层 LR / score-EMA 0.5 / box ROIAlign 14 / 无 balanced），**只改单一变量**；
- 判定标准：与三基线（0.3331 / 0.407 / 0.98585）同表比较，报告差值；bridge 指标按 Mokume/UruDendro 分域并标 GT 支持数。

## 3. 补做清单（按优先级）

### 优先级 1：闭合两个 YOLO 对照的判定矩阵（已有权重，只差评估）
1. **bridge 整图微调**（权重：本目录 `04_诊断对照实验/bridge整图微调/best.pt`，50 轮）：用 `audit_yolo_bridge_scale_domain.py` 对 bridge val/test 按 Mokume/UruDendro 分域、整图 640 与 640 tile 两种模式报告；判定线：UruDendro crack 高于零样本（0.0035/0.0715）且高于阶段三 val → bridge 在单任务下可学，多任务竞争是主因；仍接近零 → 数据域是主因。
2. **裂纹中心 tile 可学性**（权重：本目录 `04_诊断对照实验/裂纹中心tile可学性_500轮/best.pt`，实际 181/500 轮）：对 8 张 holdout 源图的 32 tile（crack 71）+ val 203 tile + ext_test 191 tile 三集合一致性评估；数据 yaml 见同目录 `data.yaml`/`data_ext_test.yaml`（或服务器 `outputs/defect_baseline/tile_learnability_yolo/`）。

### 优先级 2：+Bridge 级训练
- 启动模板：`run_stage3_nobridge_v2.sh` 去掉 `--no-bridge`，恢复 `--task-ratios "ring:2,defect:5,classification:4,bridge:2"` 与 bridge 权重 0.5；
- 服务器 GPU 约定：GPU 0/1 两卡 P100，共享服务器有他人任务（swy 等），启动前 `nvidia-smi` 确认；tmux 会话，日志 tee；
- 预计：512 steps、4 任务，约 12–15 小时/100 轮（参照 v2 11.8 小时）。

### 优先级 3：BiCRR 两级
- BiCRR = 年轮与缺陷关系建模模块（Bi-directional Cross-CR relation），当前**不建议在基础定位问题未闭合前加入**（交接报告 §12 优先级 6：增加关系模块会让因果更难判断）；等 +Bridge 结果与诊断闭环后再上。

### 优先级 4：v2 剩余差距的后备杠杆（已证据化，按需启用）
- 高 IoU 定位：box ROIAlign 14→28 或级联回归（v1→v2 已证明 14 有效：高 IoU 段 +0.12）；
- 分类：cls batch 32→64 / 分类任务占比再提 / backbone LR 再降；
- 训练策略：RPN warm-up、分域均衡采样、增加 bridge 独立物理组、调整 tile 合并（仅当诊断指向明确时）。

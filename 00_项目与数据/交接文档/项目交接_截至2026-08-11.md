## 1. 项目最终目标

本项目要建立一个同时具备以下能力的木材图像模型：

1. 年轮提取：找出年轮边界，并学习年轮距离场。
2. 缺陷检测：找出节和裂纹的位置，输出目标框。
3. 缺陷分割：输出每个节或裂纹对应的像素掩膜。
4. 缺陷分类：区分 normal、knot、crack，后续再扩展节的亚型。

阶段三采用共享编码器多任务模型：同一个 ResNet34 编码器读取 RGB 图像，年轮、检测分割和分类任务共享图像特征，再分别由不同任务头输出结果。当前版本不包含 BiCRR 关系模块。

数据按任务能力计算损失：

- 年轮数据只计算年轮损失。
- VSB 缺陷数据只计算检测、掩膜和实例分类损失。
- 分类裁剪只计算分类损失。
- 桥接数据同时计算年轮、检测、掩膜和实例分类损失。

桥接数据的核心定义是：同一张图同时具备年轮监督和缺陷监督。原年轮标注不应被改写，缺陷标注作为独立数据源读取并在内存中组合。

## 4. 新的 640×640 重叠切片方案

### 4.1 设计

大尺寸缺陷图不再整体压缩，而是在原像素尺度下切为重叠的 640×640 图块：

- tile size：640。
- overlap：160。
- stride：480。
- VSB 和 UruDendro 保持原像素尺度。
- 小尺寸 Mokume 面按比例放大到适合模型输入的尺寸。
- 原图、原 JSON、原有 train/val/test 划分均不修改。
- 图块在运行时生成，不需要把 120,000 张训练图块永久写入磁盘。

训练时，缺陷框和掩膜按图块位置裁剪；桥接图块的年轮边界、距离场和 valid mask 同步裁剪。

验证和测试时，各图块预测映射回整图坐标，同类重叠实例进行合并，再与整图真值计算指标。因此训练是局部高分辨率监督，最终评价仍然是整张原图级评价。

### 4.2 已修复的关键问题

1. 修复 bbox 备用掩膜未减去 tile 原点的问题。
2. 所有实例先在原图坐标栅格化，再统一缩放和裁剪，避免桥接细多边形在每块中重复量化。
3. VSB 和桥接验证均改为切片推理，使 `best.pt` 的选择方式与最终 test 一致。
4. 跨块预测由普通 NMS 改为按类别的实例合并，框取并集、掩膜取并集。
5. 候选掩膜使用 bit pack 暂存，降低测试回拼的内存占用。
6. 新模型从旧阶段三 `best.pt` 初始化，复用了 278 组有效参数。
7. 由于锚框从旧配置改为 thin_crack，RPN 的 4 组输出参数形状变化，未复用并重新训练。
8. 已加入可靠的 `--resume`，恢复模型、优化器、学习率调度器、AMP scaler、历史和历史最佳分数。
9. 修复 Linux 服务器上 torchvision::nms 重复注册问题，同时保留本地 Windows 兼容逻辑。
10. 用户要求将验证从每 10 轮一次改为每 5 轮一次；仍保留第 1 轮初始验证。

## 6. 当前问题

### 6.1 桥接定位仍弱

最优先问题。可能因素包括：

- VSB 与 UruDendro/Mokume 的图像域差异明显。
- 桥接训练只有 194 张原图，虽然有重叠图块，但独立场景数量仍少。
- 裂纹细长、跨 tile，预测片段只有足够重叠时才能正确合并。
- 新 thin_crack RPN 的 4 组输出参数从随机状态重新学习。
- 多任务损失相互竞争，综合分数不等价于 crack 定位最佳。

### 6.2 VSB 裂纹性能不稳定

epoch 5 的 crack AP50/Recall 高于 epoch 10，但 epoch 10 的整体 mAP 更高。需要查看 epoch 15、20 后的趋势，并按类别单独选择和报告指标。

### 6.3 尚无新模型最终 test 结果

当前全部新指标来自 val。必须等训练阶段完成并加载 `best.pt`，再只运行一次正式 test。不能把当前 val 指标直接与旧模型 test 或 YOLO test 做严格结论比较。

### 6.4 训练与验证速度慢

当前服务器为 Tesla P100 16GB，配置：

- `workers=0`，避免多进程再次造成服务器不稳定。
- `tile_eval_batch=1`，降低显存风险。
- 每 5 轮进行完整验证。

每次完整验证包含约 24,000 个 VSB 图块、308 个桥接图块，以及年轮、分类和整图参考评估。第 5、10、15 等轮次可能需要一小时或更久，`history.jsonl` 要等整次验证结束后才会写入该轮记录。

### 6.5 分类外部泛化差

分类基线内部 test 很高，但外部测试 Macro-F1 约 0.275。阶段三中的高 oracle-box 分类 F1 不能证明模型已经具备跨数据域定位能力。

## 7. 下一步计划

### 第一优先级：获得 epoch 15 完整验证

1. 确认服务器是否已写入 epoch 15。
2. 下载更新后的 `history.jsonl`。
3. 对比 epoch 1/5/10/15 的 VSB crack、bridge crack、ring 和 classification 指标。
4. 如果 epoch 15 综合或 crack 指标超过 epoch 10，继续观察到 epoch 20；否则先做定位审计，不建议盲目跑满 100 轮。

### 第二优先级：按数据来源拆分桥接验证

当前 bridge 指标把 UruDendro 和 Mokume 合在一起，无法判断到底哪个域拖累结果。下一步应分别报告：

- UruDendro box/mask AP、Recall。
- Mokume box/mask AP、Recall。
- knot 与 crack 每类指标。

这一步只改变评估报告，不应重新划分或修改 test 数据。

### 第三优先级：对当前 best.pt 做 50 张定位可视化

从 bridge val 中选择含裂纹样本，保存：

- 绿色：真实框/掩膜。
- 红色：错误预测。
- 蓝色：正确匹配预测。

需要区分以下错误类型：

- 完全漏检。
- 框位置正确但尺度不完整。
- 裂纹被拆成多个片段且未合并。
- 多条裂纹被错误合并。
- 类别正确但掩膜太粗或偏移。

### 第四优先级：根据审计结果调整训练

在看到 epoch 15/20 和可视化前，不应立即大改模型。可能的后续实验按优先顺序为：

1. 增加 bridge 任务采样比例，观察是否改善桥接定位且不明显损害 VSB。
2. 为新 RPN 增加短暂 detection/bridge warm-up，再恢复完整多任务训练。
3. 分域均衡采样，避免 bridge 中某一来源或某类图块主导训练。
4. 记录 crack 专用监控分数，避免综合 score 被 knot、分类和年轮指标掩盖。
5. 在验证集上审计 `merge_ios=0.20`，比较合并前后 Recall 和假阳性；不能用 test 调参。

### 第五优先级：速度优化

在显存烟雾测试通过后，可把 `tile_eval_batch` 从 1 尝试改为 2。P100 16GB 通常可能承受，但必须观察显存峰值。该参数只影响推理速度，不应改变结果。

不要直接把 workers 改回 4。此前多进程导致服务器崩溃；如果确需优化加载，先单独测试 workers=1 或 2，并观察内存。

### 最终验收

训练完成后使用 `best.pt` 运行一次 test，并与三个独立基线比较：

- 年轮：Mokume 已训练模型。
- 检测：YOLOv8s VSB test。
- 分类：ResNet34 分类基线。

必须分别判断共享模型是否破坏：

- 年轮 boundary Dice / distance MAE。
- VSB knot/crack 框检测。
- 缺陷掩膜质量。
- normal/knot/crack 分类。
- 桥接域联合能力。

## 10. 注意事项

1. 原始图片、原始年轮 JSON 和原始缺陷 JSON 不要改写。
2. 不要重新随机划分 bridge test，也不要用 test 调 tile overlap、置信度或合并阈值。
3. `latest.pt` 是最近完整保存轮次，`best.pt` 是综合验证分数最好轮次，两者用途不同。
4. 当前综合 best 是 epoch 10，但这不代表 epoch 10 的 crack 指标在所有轮次中最好。
5. 训练过程中没有逐 step 日志；一轮训练或完整验证期间长时间无 history 更新不等于进程卡死。
6. GPU 利用率周期性降到 0% 是 workers=0 下 CPU 读取、栅格化和裁剪造成的等待，只要 Python 进程和显存占用仍在变化通常就是正常运行。
7. 修改正式实验参数后不要直接续训旧 checkpoint。恢复逻辑会检查关键配置，避免静默混用不同实验。
8. 新切片验证与旧整图 test、YOLO test 属于不同阶段和划分，报告时必须写清 val/test，不能直接混为同一表格结论。
9. 当前切片审计证明坐标和真值回拼正确，但不能保证模型预测一定正确；最终性能仍由训练后的 test 决定。

## 11. 术语简表

- AP：单个类别在不同置信度下综合 Precision 和 Recall 的检测指标。
- mAP：多个类别 AP 的平均值。
- AP50：IoU 达到 0.50 即视为匹配时的 AP。
- AP50-95：在 IoU 0.50 到 0.95 多个严格程度下的平均 AP，比 AP50 更严格。
- Recall：真实缺陷中有多少被模型找到了。
- IoU：预测区域与真实区域的交并比，1.0 表示完全一致。
- Mask Dice：预测掩膜与真实掩膜的重叠指标。
- Macro-F1：各类别 F1 先分别计算再平均，能避免大类别掩盖小类别。
- Balanced Accuracy：各类别 Recall 的平均值，适合类别不均衡数据。
- RPN：Mask R-CNN 中负责生成候选目标框的网络。
- ROI：候选目标区域，用于进一步分类、框回归和掩膜预测。
- oracle boxes / 真实框分类：直接给分类头真实目标框，用于判断模型是否能识别框内类别；它不代表模型能自己找到目标。
- domain shift / 数据域差异：训练数据和目标数据在纹理、颜色、拍摄方式、尺度或标注风格上的差异。
- checkpoint：训练过程中保存的模型和优化器状态，可用于测试或续训。

## 12. 交接结论

截至当前，高分辨率切片、训练标注变换、测试回拼、跨块合并、数据隔离和断点续训均已完成并通过审计。新模型训练到本地快照的第 14 轮，第 10 轮是当前已验证的综合最佳轮次。

新方案已经让桥接裂纹指标从极低初值明显上升，但桥接定位和分割的绝对性能仍不足，不能宣称裂纹问题已经解决。下一位接手者应先取得 epoch 15/20 验证和分域可视化，再决定是否调整 bridge 权重、RPN warm-up 或采样策略，而不是直接改动数据划分或盲目跑满 100 轮。
